# J280 最终微调台

旋转倒立摆（GW2A-55C）的实时监视、频域分析、历史对比和“改参数→构建→烧录”工作台。

- 桥接：<http://127.0.0.1:8788/health>

## 0. 先看三条硬事实

1. **当前固件没有 UART 接收通路。** 顶层只输出 `uart_tx`，没有 `uart_rx`。网页不能在线写参数；旧文档里的 `55 AA ...` 命令、ACK 回显和 9600 波特率都已作废。
2. **遥测是 115200-8-N-1、每帧 22 字节、100 Hz。** 同步字 `AA 55`，s32 小端 Q12.16，duty 为 s16，status 一位一义；校验是 byte 2..20 的 XOR。
3. **源码不等于板上位流。** 当前 `src/` 是 v28a + 变更 A，`impl/pnr` 和板上是 v30。参数面板读的是**源码常量**；第一次构建会把“v28a+A”烧进去，而不是重烧 v30。

## 2. 串口与数据

浏览器（Chrome / Edge）通过 Web Serial 独占 CH340：

| 项 | 值 |
|---|---|
| 波特率 | 115200 |
| 数据格式 | 8-N-1，无流控 |
| 帧长 | 22 字节 |
| 帧头 | `AA 55` |
| 频率 | 100 Hz |
| 字节 2..17 | theta_err / dtheta / alpha / dalpha：4 × s32 LE Q12.16（÷65536） |
| 字节 18..19 | duty：s16（±1000） |
| 字节 20 | status：`[1:0]` FSM，`[2]` lqr_en，`[3]` swing_en，`[4]` motor_active，`[5]` energy_deficit，`[6]` calib_done |
| 字节 21 | XOR(byte 2..20) |

页面只负责接收，不会向板子写任何字节。CSV 列：

```text
time,theta_rad,dtheta_rad_s,alpha_rad,dalpha_rad_s,duty,status
```

`time` 是网页接收时刻 `HH:MM:SS.mmm`；历史 CSV 用同一格式。

## 3. 页面能做什么

- **三维姿态**：摆臂 + 摆杆建模，按 alpha/theta 实时投影；带末端轨迹和数值读数。60 fps 刷新，不做物理积分，只做显示平滑。
- **时域**：θ / α / duty 三通道，5/10/30/60 s 或全窗口；双轴刻度、22°/45° 参考线、duty ±1000/±432 参考线；可打标记、清空。
- **频域**：Hann 窗 FFT（目标窗 5.12/10.24/20.48 s），0–25 Hz 谱线 + 20 s 滚动瀑布图（每列 2.56 s、约 220 ms 更新）。实际 N 随可用数据自适应，**不会补零**：FFT 是 2 的幂，最小可用 256 点（2.56 s），**不足 2.56 s 不报主频/音调幅**；没有 BALANCE 段时同样不报。指标面板与谱图共用 FFT 窗选择。
- **稳定度与噪音**：θ σ、α σ（去均值标准差）、duty 标准差、duty 2–20 Hz 音调幅（FFT 找峰后用锁相估计）、主频（抛物线插值细化）、饱和占比（|duty| ≥ 1000）、首捕保持、起摆→首捕时长、最长平衡、θ 高频噪声。稳定段取最长 BALANCE 段并跳过前 2 s；没有 BALANCE 时统计退回全段并在界面上明确标注，但频域指标留空；稳定段少于 32 点（0.32 s）时 σ/噪音/饱和留空，避免小样本退化成“很稳”。与文档里固定 30–80 s 窗口的数值**不可直接比较**。
- **历史对比**：读项目 `data/*.csv`，或用“保存本次”把当前数据写回 `data/web_*.csv`；同窗口重采样后叠加平衡段，表里按同一估计器给指标。
- **参数面板**：21 个可写常量，按组显示当前源码值、单位、范围和用途。
- **构建/烧录**：把面板值写回 RTL、调用 `gw_sh`、检查时序/DSP、归档位流，可选 SRAM 烧录；另有“恢复上次备份”按钮，用 `tune_backups/` 最近一次构建前备份覆盖 `src/`（与构建互斥）。
- **板载按键说明**：见第 6 节。

## 4. 参数进板流程（约 1–3 分钟）

```text
页面参数 → POST /tune/build → 备份源文件 → 正则替换常量
→ gw_sh build.tcl → 解析 Fmax/slack/DSP → 归档 versions/tune_*.fs
→ （可选）programmer_cli -r 2 SRAM 烧录 → 记录 tune_runs/*.json
```

安全门：

- 烧录必须勾选“摆杆已扶稳、SW3 电机使能为关”，并在页面输入 `BURN`；页面还必须提交 `safe_ack: true`，桥接端会校验（仍不能替代人工确认物理状态）；
- 必须给**全部 21 个参数**；任一范围/交叉检查失败，构建前同步拒绝（返回 400，不创建任务）；
- 构建后位流必须是本次新生成的；CheckSum 必须可读、文件 >100 KB；
- **DSP 必须是 20/20**；Setup/Hold slack 必须 ≥ 0 且字段齐全；Fmax 必须 ≥ 50 MHz；时序报告必须是本次构建生成。任一不满足即判构建失败，不会归档、不会烧录；
- 每个改动的源文件在 `tune_backups/<时间戳>/` 有逐字节备份；
- 位流归档到 `versions/tune_<时间戳>_<CheckSum>_<sha256 前 8 位>.fs`，归档后复算 SHA-256，日志写到 `tune_runs/`；
- 构建与“恢复备份”共用源文件锁，互斥执行；构建进行中再提交会返回 409。

注意：

- `programmer_cli -r 2` 是 **SRAM 运行**，掉电/重新上电后回到 flash 里的旧位流。
- 烧录后 SW1 的零位标定失效，需重新标定。
- “仅构建”不会动板子；构建结果仍需人工决定是否烧录。
- 构建会重写源码常量。构建失败时源码保持已改状态，页面日志给出备份路径，可 `POST /tune/restore` 恢复。

## 6. 板载按键

| 键 | 操作 | 作用 |
|---|---|---|
| SW1 | 按住 ≥20 ms 后松开 | 锁存当前 ADC 为竖直零位；复位/重烧后失效 |
| SW2 | 短按 | 轨迹模式 0° → +45° → −45° → 0.2 Hz 正弦循环 |
| SW2 | 长按 ≥0.7 s | 转臂位置清零，同时清 PID 慢积分（首捕实验前用） |
| SW3 | 按一次 | 电机使能翻转；上电默认关 |
| SW4 | 按一次 | 停机模式翻转：0 自由滑行，1 动态制动 |
| SW5 | 按一次 | 异步复位：状态机、标定、使能、轨迹全部回默认 |

上电 SOP：扶正摆杆 → 短按 SW1 标定 → 短按 SW3 使能 → 自动起摆。烧录前扶稳摆杆并确认 SW3 为关。

### 7.1 本地接口的访问限制

桥接只监听 `127.0.0.1:8788`，并额外校验：

- **Host 白名单**：`127.0.0.1:8788` / `localhost:8788`，其他 Host 返回 403；
- **Origin 白名单**：带 `Origin` 的请求只接受 `http://127.0.0.1:8787`、`http://localhost:8787`；其他 Origin 返回 403；
- 不带 Origin 的本机命令行请求（如 PowerShell `Invoke-RestMethod`）仍可用；
- 所有写操作必须是 JSON（否则 415）；
- 响应不使用 `Access-Control-Allow-Origin: *`，并带 `Cache-Control: no-store`；
- 烧录请求必须带布尔 `safe_ack: true`；字符串 `"true"` 不被接受。

这些限制防的是浏览器跨站请求，**不能**防本机其他进程，也不能验证摆杆是否真的扶稳。物理安全仍由人负责。

## 8. 排错

| 现象 | 原因 | 处理 |
|---|---|---|
| 8787 打不开 | 静态服务没起/端口占用 | 查 8787 占用，只保留一个实例 |
| 页面“桥接未连接” | 8788 没起 | 启动 `python live_bridge.py` |
| 已连接但 0 帧/s | 波特率/端口/板子没跑 | 确认 115200、CH340、位流已烧 |
| 帧有但坏帧多 | 同步字/校验/线序 | 看“原始字节”，确认 `AA 55` 与 XOR |
| 构建失败在 patch 阶段 | 源码常量被改过，正则不唯一 | 看日志中的参数名和文件；先恢复备份 |
| 拒绝烧录 | slack 负 / Fmax < 50 / 位流未更新 | 只构建，不改板；检查 DSP 是否 20/20 |
| `gw_sh` 找不到 | 工具路径变 | 设置环境变量 `J280_PROJECT_DIR`，或改脚本顶部 `GW_SH` |
