# K230 手势控制（创新点）— 使用说明

文件：`j280_gesture.py`
平台：K230 CanMV（LCD 640×480）
模型：复用 `/sdcard/kmodel/yolov8n-pose.kmodel`（**只读**）

---

## 1. 和原项目共用一张 SD 卡，会不会混？

不会，前提是按下面的目录放：

```text
/sdcard/
├── main.py                    ← 原项目入口，不要动
├── kmodel/
│   └── yolov8n-pose.kmodel    ← 两个项目共用，本脚本只读
├── audio/                     ← 原项目语音，不要动
└── j280_gesture/              ← 只新增这个目录
    └── j280_gesture.py
```

规则：

1. **不要覆盖 `/sdcard/main.py`**。原项目靠它开机自启；我们不改名、不删除。
2. **不要动 `/sdcard/kmodel/` 和 `/sdcard/audio/`**。脚本只读取姿态模型。
3. 本脚本不写任何文件，断电不会留下状态。
4. 在 CanMV IDE 里运行本脚本时，会顶掉正在跑的 `main.py`；IDE 停止/重启板子后，原项目照旧。
5. 如果以后想让本脚本开机自启，建议换一张 SD 卡，而不是改原卡上的 `main.py`。

## 2. 手势表

| 手势 | 判定条件（简） | 输出 `arg` | 建议映射 |
|---|---|---|---|
| 左臂侧平举 | 左臂伸直、接近水平、向身体外侧 | `left` | 转臂逆时针 |
| 右臂侧平举 | 右臂伸直、接近水平、向身体外侧 | `right` | 转臂顺时针 |
| 双臂上举 | 双手都高于肩、手臂基本竖直 | `stop` | 停止 / 回零 |
| 自然下垂 | 双手低于肩 | 无 | 复位，允许下一次触发 |

触发规则（r4）：

- 手势要**保持 500 ms** 才发命令；
- 最近 5 帧里 **3 帧一致** 才作为候选，抗关节抖动；
- 发完命令后，只要**刚做动作的那只手放下 300 ms** 就重新允许触发，不要求双手同时放下；
- 两次命令至少间隔 **800 ms**；
- 两侧手臂关键点都必须可信（置信度 ≥ 0.35），遮住一只手不会误触发；
- 屏幕会提示 `READY` / `LOWER LEFT ARM TO REARM` / `LOWER RIGHT ARM TO REARM`。

## 3. 在 CanMV IDE 里测试

1. 把 `j280_gesture.py` 复制到 `/sdcard/j280_gesture/`（目录不存在就新建）。
2. 打开 CanMV IDE，连接 K230，打开这个文件。
3. 直接点运行（绿色三角）。模型路径是绝对路径，文件放在电脑上运行也能找到模型。
4. 人站在摄像头前 **1.5–2.5 m**，画面里露出完整上半身和双手。
5. 画面输出由文件开头的 `DISPLAY_MODE` 控制：
   - `"lcd"`（默认）：K230 的 LCD 正常显示，同时用 `to_ide=True` 尽量镜像到 IDE 帧缓冲区；
   - `"virt"`：只走 USB 输出到 CanMV IDE 帧缓冲区，不驱动 LCD。
   如果 `"lcd"` 时 LCD 正常但 IDE 一直黑屏，先把 `DISPLAY_MODE` 改成 `"virt"` 验证 IDE 通道；两者能否同时显示取决于板子固件对 `to_ide` 的支持。
6. 看屏幕：
   - 顶部 `GESTURE:` 显示当前识别结果；
   - 中间绿色进度条表示保持时间；
   - `READY` = 允许触发；`LOWER ... TO REARM` = 需要把刚才那只手放下；
   - 触发后显示 `SENT: left/right/stop`；同档位重复显示 `ALREADY: ...`；
   - 底部显示 FPS 和 TCP 开关状态。
7. 看串口（CanMV IDE 下方终端），每 200 ms 一行：

```text
GESTURE,left_arm,L:side R:low sw:112,voted=left_arm,hold=0.62,armed=1
GESTURE_FIRE,left_arm,left same=0
CMD_DRYRUN,{"type":"cmd","cmd":"gesture","arg":"left","seq":1,"t_ms":12345}
```

`ENABLE_TCP = False` 时只打印 `CMD_DRYRUN`，**不会连 ESP32**，可以放心先调手势。

## 4. 现场调参（文件开头配置区）

| 参数 | 默认 | 什么时候改 |
|---|---|---|
| `HOLD_MS` | 500 | 误触发多 → 加到 650–800；反应慢 → 减到 400 |
| `RELEASE_MS` | 300 | 连续触发/同手反复触发 → 加到 400–500 |
| `COOLDOWN_MS` | 800 | 想快速连续切档 → 减到 600，不建议低于 500 |
| `SWAP_LEFT_RIGHT` | False | 实测左右反了 → 改 True |
| `SIDE_DY_MIN/MAX` | -0.45 / 0.40 | 侧平举识别不到 → 放宽（如 -0.55 / 0.50） |
| `SIDE_LAT_MIN` | 0.70 | 手臂伸得不够开 → 减到 0.60 |
| `UP_DY_MAX` | -0.45 | 双臂上举识别不到 → 改成 -0.35 |
| `LOW_DY_MIN` | 0.55 | 自然下垂识别不到 → 减到 0.45 |
| `KP_MIN` | 0.35 | 关节点抖动大 → 加到 0.45 |

调试时看每行 `GESTURE,...` 里的 `L:*/R:*`：

- `side` = 侧平举；
- `up` = 上举；
- `low` = 下垂；
- `mid` = 中间状态；
- `none` = 关键点不可信。

按实际显示调整阈值，比盲改快。

## 5. 输出协议（后面接 ESP32 用）

```json
{"type":"cmd","cmd":"gesture","arg":"left","seq":1,"t_ms":12345}
```

- `arg`：`left` / `right` / `stop`
- `seq`：递增序号，ESP32 可用来去重
- `t_ms`：K230 本地毫秒时戳

ESP32 固件收到后转成 FPGA 的 UART 命令即可；FPGA 端的 `cmd_uart_rx` 还没写，**当前只能到 ESP32 为止**。

如果要直接把 K230 接到 FPGA（跳过 ESP32），把 `ENABLE_TCP` 的逻辑换成 UART 发送即可，手势判定部分不用动。

## 6. ESP32 转发与 FPGA 接收

> **烧录与联调步骤见 `README_烧录与联调.md`**：ESP32 用
> `esp32_project_fpga/flash_app_esptool.bat`，FPGA 用
> `fpga_cmd/patched_0xD0FA/Flash_patched_cmd_0x6A4D.bat`。

| 目录 | 内容 |
|---|---|
| `esp32_bridge/` | 新增的 `fpga_link.c/.h`，把 K230 的 TCP JSON 手势转发到 UART1；集成步骤见 `INTEGRATION.md` |
| `fpga_cmd/` | 新增的 `j280_cmd_rx.v` + 自检测试台；档位注入步骤见 `INTEGRATION.md` |
| `fpga_cmd/patched_0xD0FA/` | **已按最新 0xD0FA 集成并构建通过**：位流 `patched_cmd_0x6A4D.fs`，Fmax 50.110 MHz，0/0，DSP 19/20 |

串口协议（ESP32 → FPGA，115200-8-N-1）：

```text
AA 55 CMD ARG CHK        CHK = CMD ^ ARG ^ 0x5A
CMD 0x01 SET_MODE  ARG 0..5
CMD 0x02 STOP      回 0°
CMD 0x03 NEXT      下一档
CMD 0x05 HEARTBEAT 每 500 ms
```

默认映射：

```text
left  -> mode 4 (-90°)
right -> mode 3 (+90°)
stop  -> mode 0 (0°)
```

两个文件夹里的文件都是**新增**的，`I CAN Contest` 原工程和 `v35_ext` 都没有被改动；集成时按各自 `INTEGRATION.md` 手动加几行。

## 7. 已知限制

1. **数字手势暂不支持**：当前用的是 YOLOv8n-pose，只能看身体关键点，没有手部 21 点模型。要识别 1–6，需要另加手部关键点 kmodel，工作量比手势切换大。
2. **一次只能锁一个人**：画面里多人时选离画面中心最近的那个；演示时保持背景干净。
3. **强逆光/宽松衣服**会掉关键点；掉点时脚本不会发命令，这是有意的安全设计。
4. 本脚本**不直接控制电机**。在 FPGA 命令解析和限幅写完之前，保持 SW3 电机使能关闭。
